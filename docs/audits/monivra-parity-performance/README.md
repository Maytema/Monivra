# Аудит: соответствие, скорость, ветки (14.11.2026)

Сравнение браузерной версии Monivra (Capacitor/WebView, эталон) и новой версии на React Native — по
исходникам и **на одном и том же эмуляторе с одними и теми же данными**. Аудит ничего не меняет в коде
приложений: только скрипты в `tools/audit/`, workflow `.github/workflows/audit.yml` и документы в этой папке
(ветка `audit/parity-performance`). Ни одна ветка не удалена, ничего не слито.

## Как проводилось

1. **Инвентарь** (`node tools/audit/inventory.mjs`): из исходников старого приложения (`js/`) собраны
   экраны, переходы `openPage`, окна `openSheet`/`confirmAction`, кнопки и действия; каждый элемент ищется в
   коде нового (`mobile/src`) по надписи и по карте экранов; отмечается, нажимался ли он в эмуляторном обходе
   нового приложения.
2. **Две версии на одном эмуляторе** (`.github/workflows/audit.yml` → `tools/audit/compare.mjs`): release-
   сборки обеих версий ставятся на один эмулятор Android 14; в обе загружается один файл данных (3000
   операций за 18 месяцев) через их собственный экран «Восстановить из файла»; затем одинаковые касания —
   холодный запуск ×3, вкладки, броски списка операций, свайпы периода на трёх вкладках, прокрутка
   статистики, список валют (открытие, броски, кадр в середине броска). Кадры — `dumpsys gfxinfo
   framestats`; «успокоение» — конец серии кадров до первой паузы 250 мс. Скриншоты каждой точки.
3. **Причины** — чтение кода по результатам замеров; всё, что не подтверждено профилировщиком, помечено
   гипотезой.
4. **Ветки** — `git ls-remote`, сравнение достижимости коммитов, ссылки в workflow, открытые PR.

Повторить: `git push` в `audit/parity-performance` (или «Run workflow» у «Audit (old vs RN on one emulator)»);
результаты появятся в ветке `audit-results`, папка `runs/<номер прогона>/`.

## Главное

- **Скорость.** На эмуляторе новое приложение **не медленнее** старого в запуске (быстрее в ~2 раза) и в
  свайпах периода (на категориях быстрее в ~2,4 раза). Отстаёт в прокрутке статистики и, по первому прогону,
  в бросках длинных списков — причины и их статус в `PERFORMANCE_ROOT_CAUSES.md`. Список валют: механизм
  пустых строк найден в коде (виртуальный список без размеров строк), исправление — BL-P1-02.
- **Соответствие.** На 6 сравненных экранах суммы, порядок и состав совпали; 14 визуальных пунктов: 3
  совпадают, 9 отличаются (6 — намеренно по эталонным снимкам, ждут решения владельца; 3 — мелкие дефекты),
  1 функциональное расхождение (график статистики), 1 намеренное улучшение. Из 426 окон и действий старого
  вживую в новом нажимались 100; остальное найдено в коде, но поведение не сверено.
- **P0 не найдено.**
- **Ветки.** Monivra: 30 веток — 8 оставить, 19 кандидатов на удаление (все коммиты уже в `main` или
  `rn-migration`), 2 на ручное решение. Ничего не удалено.

## Ограничения (честно)

- Эмулятор с программной графикой: абсолютные времена кадров выше телефонных; сравнивать только версии между
  собой. Телефона владельца в проверке нет.
- Старое приложение рисует через WebView: часть его кадров композитор Chromium делает сам, `gfxinfo` их видит
  не все. Поэтому главная метрика — время до успокоения, а не число кадров.
- Снятие дерева экрана (`uiautomator dump`) включает службу специальных возможностей и нагружает приложения;
  с прогона 5 элементы ищутся до начала замера, и перед замером пауза 1 с.
- Один прогон — это одна выборка; разброс между повторами в пределах прогона виден в таблице (по 3 повтора).
- Вне доступа: другие репозитории учётной записи, кроме трёх видимых; GitHub Artifacts (скачивание закрыто в
  этой среде — поэтому результаты публикуются в ветку).
