# Бэклог по итогам аудита

P0 — мешает пользоваться или теряет данные; P1 — заметно владельцу / нужно для честного сравнения;
P2 — качество и надёжность; P3 — улучшения. «Быстро» — правка в одном месте, часы; «Архитектура» —
меняет устройство, нужен замер до/после и решение владельца.

P0 в этом аудите **не найдено**: потерь данных и падений на общих сценариях обеих версий нет (восстановление
3000 операций, вкладки, свайпы, список валют прошли в обеих версиях, суммы совпали). Одно наблюдение
по старому: в прогоне 7 оно закрылось после системного окна выбора файла (в прогонах 4 и 8 — нет); причина не
установлена, журнал падений в том прогоне не снимался.

## Порядок, который я бы предложил

1. BL-P1-01 (lock-файл) → BL-P1-04 (пороги) — чтобы каждое следующее исправление было измерено честно.
2. BL-P1-02 (первое открытие «Операций») — самое большое устойчивое отставание; затем 02a, 02b, 02c.
3. BL-P1-03 (график) — быстро и видно владельцу.
4. BL-P1-07 (телефон) — прежде чем трогать свайп периода (BL-P2-04).
5. BL-P1-05 (общий сценарий) — параллельно, он же закрывает визуальную сверку остальных экранов.
