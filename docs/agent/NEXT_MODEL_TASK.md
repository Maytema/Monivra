# Задание: довести нативное приложение Monivra до полного совпадения с браузерной версией и убрать тормоза

Для модели, которая продолжает работу. Сначала прочитай `CLAUDE.md` и `docs/AGENTS.md` (правила работы, деньги, данные, Git, секреты), потом этот файл, потом только документы той области, которую трогаешь (таблица в `docs/AGENTS.md`).

## 1. Цель одной фразой

Получить приложение, которое **один в один выглядит и работает как браузерная версия (WebView)**: все экраны, окна, кнопки, жесты, тексты, поведение — до мельчайших деталей, и при этом **не лагает**. Сейчас оно работает, но медленно и местами не так, как старое. Главный приоритет: сначала **скорость и отсутствие тормозов**, затем остаток расхождений.

1. Владелец — начинающий разработчик, пишет по-русски с телефона. **Все ответы ему — по-русски, коротко, утверждать только то, что проверено.**

Секреты: ключ подписи и пароли лежат в `…/scratchpad/keys/github-secrets.txt` (вне репозитория, **только в окружении, где работала предыдущая модель**). **Никогда не печатать, не коммитить, не логировать.** Не трогать ветки `main` и `android-first-apk`. ## 4. Как работать и проверять (важно для скорости)

- Не собирай APK после каждой мелочи. Цикл такой: правка → локальные проверки → накопить заметный объём → push → CI → смотреть скриншоты. **Когда накопится значимый кусок работы, собери APK, подпиши ключом владельца и отправь ему на проверку** (владелец сам просит промежуточные APK, не жди «полной готовности»).
- Локальные проверки из `mobile/`: `node --test test/*.test.ts` (сейчас 90 тестов проходят), `node scripts/check-boundaries.mjs`, типы (в окружении без сети `tsc` заглушён скриптом `…/scratchpad/tscheck/run.sh`; если у тебя есть `npm ci` и сеть — запускай настоящий `tsc`).
- CI: `.github/workflows/mobile.yml` (типы, тесты, сборка APK arm64 и x86_64, **эмуляторный тур** `mobile/scripts/emulator-smoke.sh`, публикация в ветку `mobile-builds`). Тур снимает ~120 скриншотов и пишет `steps.txt`, `js-log.txt`, `perf.txt`, `crash.txt`.
  - Результаты: `git fetch origin +refs/heads/mobile-builds:refs/remotes/origin/mobile-builds`, затем `git archive origin/mobile-builds builds/<N>/emulator | tar -x -C /tmp/x`. Старые скриншоты для сравнения: `tools/tour/crawl-old.mjs`.
  - **Новый push отменяет идущий CI-запуск**: пушь, когда предыдущий закончился, если нужны скриншоты. Сбой «NDK download / Error reading Zip» — сбой сети GitHub, лечится `gh run rerun <id> --failed`.
  - Эмуляторный тур уже поймал настоящие вылеты (например, два драйвера анимации на одном элементе). Расширяй тур вместо ручных догадок.
- Подпись APK: CI публикует `RESIGN-ONLY-monivra-rn-<N>.apk` (временный ключ). Владелец ставит поверх своей сборки, поэтому APK нужно переподписать **его** ключом: скрипт `…/scratchpad/resign.sh <вход.apk> <выход.apk>` (печатает только отпечаток сертификата; ожидаемый SHA-256 сертификата начинается с `7e041ae5…bc9784`). Если скрипта и ключа нет в окружении — скажи владельцу, не придумывай ключ.
- Установка пакетов (`npm`/`pip`) в прежнем окружении была отключена. Если в твоём окружении сеть есть — можно ставить зависимости, но обновляй `package.json` и lock-файл и убедись, что CI соберётся.

## 5. Что владелец нашёл на телефоне (сборка 63) — сделать в первую очередь

### 5.1. Тормоза (главное)
Приложение в целом **медленно работает и тормозит**. Найти **причину**, а не латать симптомы:
- Измерить и найти горячие места: разделы «Операции» (длинный список, группировка по дням, период, свайп между периодами), «Статистика» (диаграмма), экран блокировки, открытие окон/листов, переход между вкладками. Используй `perf.txt` из тура, профилировщик Hermes/React DevTools, замеры времени в `__DEV__`.
- Проверь подозреваемых: лишние перерисовки при каждом изменении ledger (контекст отдаёт весь `data` всем компонентам — нужны селекторы/мемоизация); тяжёлые вычисления на каждый рендер (`operationsIn`, `reportRows`, форматирование денег/дат); `FlatList` без стабильных ключей/`getItemLayout`/оконного режима; анимации на JS-драйвере там, где можно нативный; `Intl` в Hermes медленный (решение 0003 — форматируем вручную, не возвращай `Intl`); синхронные вызовы SQLite на главном потоке; SVG-диаграммы, перерисовываемые целиком.
- Критерий: нажатие и ввод цифр отзываются сразу (кадр < ~16 мс), списки листаются без рывков, вкладки открываются мгновенно. Зафиксируй цифры до/после в `docs/architecture/`.

### 5.2. Экран блокировки (`mobile/src/features/lock.tsx`)
1. **Цифры уходят под системную панель навигации внизу** — учесть нижний inset (`useSafeAreaInsets`), клавиатура целиком над панелью на любом телефоне.
2. **Вместо знака доллара — логотип Monivra** (компонент логотипа есть: `mobile/src/ui/brand-mark.tsx`; сверь с логотипом старой версии).
3. **Очень медленно:** последняя введённая цифра **не закрашивает ячейку**, как остальные, а вход открывается только через пару секунд после верного PIN. Причина, вероятно, в проверке PIN (PBKDF2 в JS на Hermes — медленно, и она блокирует поток до перерисовки). Сначала отрисовать закрашенную последнюю точку (дать кадру отрисоваться), потом проверять; проверку сделать быстрой (нативная реализация/меньшее число итераций с пересмотром безопасности в `domain/pin.ts` — это записать в решения, либо вынести в нативный модуль / `expo-crypto`). Верный PIN должен открывать приложение практически мгновенно.
4. **Неверный PIN:** тоже медленно. Должно быть: сразу встряхнуть **все ячейки** (они при этом пустеют), показать «Неверный PIN», дать вибрацию.
5. **Вибрация (haptics) — умеренно, только для важного:** неверный PIN, отказ (например, неподходящий фото-файл), подтверждение опасных действий, успешное важное действие по смыслу. Не вибрировать на каждое нажатие. Сделать **одним общим модулем** (например, `platform/haptics.ts`: `haptic("error" | "success" | "warning")`), использовать `expo-haptics` (добавить зависимость) или `Vibration` из React Native с разрешением `VIBRATE`. Уважать настройку системы.

### 5.3. Превью отчёта/экспорта (предпросмотр PDF/таблицы, шкала «n из 94»)
Сейчас окно открывается почти мгновенно, но **дальше в фоне ничего не подгружается**, подгрузка начинается только при пролистывании — из-за этого человеку приходится ждать. Нужная логика:
- При **первом открытии** не открывать «моментально»: показать окно с индикатором прогресса «N из M страниц» и подождать, пока подготовится **первая часть** (несколько страниц).
- Как только первая часть готова — показать превью и **продолжить подготовку остальных страниц в фоне**, даже если человек не листает.
- **Кэшировать** уже подготовленные страницы (по ключу: параметры отчёта + версия данных), чтобы повторное открытие было быстрым и не пересчитывалось заново; сбрасывать кэш при изменении данных/параметров.
- Код: `mobile/src/features/export-page.tsx`, `mobile/src/application/report/` (job, pdf), старый `js/screens/export.js`, `js/screens/export-preview.js`.

### 5.4. Статистика: диаграмма (`mobile/src/features/statistics.tsx`, старый `js/screens/statistics.js`)
Диаграмма плохо понятна: нажимаешь на доли — неясно, как это работает, а если ничего не выбрано, **центр пустой**. Сделать: в центре диаграммы, когда ничего не выбрано, показывать **общую сумму за период** (расход или доход — смотря какая вкладка выбрана); при выборе доли — название, сумма и процент; выделение выбранной доли должно быть наглядным и обратимым (повторное нажатие снимает). Сверить с логикой старой версии и не потерять её поведение.
